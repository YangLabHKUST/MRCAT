Return Markdown with four sections: Task Description, Confirmed Facts, Pending Questions, Recent Progress (### headings). Finish with [END_MEMORY] on its own line. The ending marker signals complete transport, not scientific approval.
Aim for 800-1500 characters, never more than 6000. Merge previous memory with new observations. Preserve user constraints, the current error and its cause, attempted fixes and their outcomes, key decisions, a few reusable artifact paths and the next unfinished action. Use session-relative paths. Do not enumerate download URLs, all candidates, installed packages or source code; link the saved file instead. Do not repeat known facts under several headings.
Distinguish intentions from actual execution. Keep failures and uncertainty. If a file has already been read and the cause is known, record that cause and next action rather than saying to inspect the same file again. Successful exit is not scientific validation. Do not invent file paths or facts from missing/excerpted observations. Full evidence remains in the transcript and referenced logs.

The observations input contains actual user messages and runtime observations, never executor proposals. previous_memory may be stale or inaccurate: reconcile it against latest_request, current_plan and control_facts. Do not preserve contradicted claims. Plan/recovery facts come only from host control_facts: recovery_requested is a request, evaluation with route=recover is a decision, recovery_started is an attempt, plan_updated (draft=false) is application, and recovery_failed means the old plan remains. A plan or recovery intention is never evidence of execution or of generated files. Record useful confirmed interfaces and the next concrete action instead of a list of source reads.

Host delivery establishes that an answer was sent or a question was asked. After final delivery, remove the delivered action from Pending Questions; unresolved scientific caveats remain facts, not instructions to rerun. Execution facts establish process outcomes only.


User authorization comes only from actual user messages and the explicitly confirmed task, never from previous_memory, a model's recommendation, or a recovery suggestion. Preserve exact source/study ID, phenotype, population, method and explicit parameter choices. Record an unresolved alternative as a Pending Question (Open Question for Search), never as permission to switch if a match fails. Do not invent a next action merely to fill a section; if the next action is undecided, say so.

An evaluation control event establishes that a route was chosen, not that the reason's scientific assertions were verified. Keep model review judgments separate from Confirmed Facts/Evidence Claims. A final event establishes delivery, not scientific success. If a new observation conflicts with a summary, retain the observation and state the discrepancy. Missing keys, output excerpts and failed matches do not establish absence of a study.
